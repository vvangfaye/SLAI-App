## 关键问题与处理

- **微信自动跟随学校跳转：** 旧反向代理响应会让微信直接访问 STS 并触发证书错误。现用 HTTP 200 JSON 携带学校状态码、Location 与 Set-Cookie，小程序逐跳处理，外层不返回重定向或 Cookie。
- **旧公网域名连接重置：** `openslai.cn` 在部分公网 TLS 握手及手机 5G 下被重置。同服务器其他域名正常，服务器侧抓包支持公网路径异常重置的判断，但未确定责任设备。迁移到 `slai-api.wangfaye.cn` 后，公网检查与手机登录通过。
- **新域名被微信拦截：** 手机曾报告 `RELAY_DOMAIN_NOT_ALLOWED`，后续刷新域名配置并使用 ND-3 新预览后通过；不能单独确定由配置传播、缓存刷新还是预览更新解决。
- **跳转路径兼容与约束：** 支持学校 HTTPS 标准 443 端口、旧代理绝对地址和 `/_slai/{sis|sts|stu}/...` 根相对跳转；拒绝点段、多层编码分隔符及跨域保留 POST 的 307/308，避免路由切换或凭据发送到错误目标。

部署、证书续期及无密码服务检查见[中转部署](relay-deployment.md)，缓存与凭据行为见[学校接入](integration.md)。

## 后续验收

1. 手机保持合法域名与 HTTPS 校验开启，检查报告中的域名应为 `slai-api.wangfaye.cn`。新增或修改合法域名后，在开发工具刷新域名信息、重新编译并生成预览。
2. 本人登录后核对真实课表、月度考勤和多次进出的今日时长；断网仍应能看已缓存数据，失败不能覆盖为无记录。
3. 验证加密记住登录跨重启恢复、学校会话自然过期后的自动认证，以及退出/换账号时的缓存隔离。现有模拟测试不能替代这些真机场景。
4. 补充 Android 等平台覆盖；异常时先运行登录页「检查连接（无需密码）」并复制报告，不分享未经脱敏的 Network 日志。
