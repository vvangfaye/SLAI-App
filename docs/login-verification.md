# 微信内登录并读取学校数据：验证记录

验证日期：2026-09-11。

## 目前结论

**微信小程序直接认证、读取课表和考勤的核心链路已通过本次真机验证。** 手机截图确认教务接口返回 3 条课程记录；随后用户确认开启 VPN 后，小程序与学生系统网页均正常。考勤成功依据用户真机反馈，未另行采集原始考勤响应。本次测试说明无需依赖 Android WebView 或自建后端即可完成这条链路；当前测试网络下访问考勤需要 VPN。主页面现已接入真实同步代码；新月汇总、节次时间接口和页面显示仍需真机验收。

## 微信官方文档确认

- [wx.request](https://developers.weixin.qq.com/miniprogram/dev/api/network/request/wx.request.html) 返回 `cookies`；基础库 3.2.2 起支持 `redirect: manual`，文档说明安卓、iOS 与开发工具已支持。支持 GET/POST，但不能自定义 Referer。
- [onHeadersReceived](https://developers.weixin.qq.com/miniprogram/dev/api/network/request/RequestTask.onHeadersReceived.html) 返回 header、cookies、statusCode；文档指出开发工具可能不返回 statusCode，需真机核实。代码遇到未知状态码不会假定为 302。
- [网络能力](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html) 要求配置合法通讯域名。测试时关闭校验不能作为普通真机上线可用的证据。
- [web-view](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html) 的限制仍成立；本次候选路线完全不使用该组件。

由此推断：小程序可能自己处理学校 GET → AD FS POST → 授权码回调 → SIS Cookie → 业务 API 的链路，无需获取已有浏览器 Cookie，也不需要修改学校 OAuth 客户端回调地址。但请求是否被接受、全部重定向是否可用，必须由实测确认。

## 已准备的实验代码

`miniprogram/pages/probe/index` 是独立开发验证页，没有放入普通用户导航。项目已配置“学校登录验证”编译模式，选择该模式即可。

1. 实际 AppID 已写入本地项目。已在对应小程序后台配置 `https://sis.slai.edu.cn`、`https://sts.slai.edu.cn`、`https://stu.slai.edu.cn` 三个 request 合法域名；确认基础库 >= 3.2.2。
2. 在能够访问学校系统的网络中真机预览。
3. 在验证页本人输入校园账号密码，只点击一次验证。无需把密码发到聊天。
4. 代码只向 `sts.slai.edu.cn` 的已识别认证表单提交密码，不经过自建后端。跟随 GET/POST 重定向时按域名、路径管理内存 Cookie。拒绝非学校域名，以及跨域保留 POST 的 307/308。
5. 登录后读取学期，再验证课表 kbList 数组；尝试通过 SSO 访问 STU 并读取最多一条闸机记录。如果 STU 要求再次登录，停止而不再次自动提交密码。
6. 页面只显示阶段、条数和错误类别，不显示原始响应、Cookie 或密码；结束时清空会话。开发调试器本身仍可能显示网络请求，应避免导出或分享未经脱敏的网络日志。

此代码是协议探针，不是完整认证产品。它未处理 MFA、图片验证码、各种学校错误页面、长期续期、退出时学校会话撤销、完整考勤分页或实时同步。遇到不认识的流程停止，不进行重复密码尝试。

## iCloud 填充排查（2026-09-11，尚未解决）

用户在重新生成的 iPhone 预览版中，多次反馈 Face ID 成功后密码没有填入。表单取值、绑定值同步和 `change` 事件处理均未解决真机现象；通过的 Node 测试只证明事件处理逻辑，不证明 iOS 原生自动填充可用。

新增 AF-1 检查：在开发/体验版的登录页点击「填充帮助 → 检查填充」。对照表单不绑定 `value`，输入和焦点事件不调用 `setData`、不改变焦点，只收集字段名称、事件类型以及是否非空。点击「检查」后移除原生输入框，展示只含这些布尔状态和系统/微信/基础库版本的报告。不会认证、请求网络、写入凭据缓存或记录密码内容、长度。用户可选择复制报告。正式版不启用检查页。

待手机结果确认：若对照表单也未收到值，则问题仍在 iOS/微信交付输入内容的环节；若对照成功，再对照登录页事件顺序定位绑定或焦点问题。尚不能判定具体平台缺陷，也不能宣称 iCloud 填充已修复。临时可从系统「密码」复制并长按输入框粘贴。

AF-1 已在开发者工具用虚构账号/密码验证空值报告和有值报告，30 项本地测试通过。连续同状态按键事件合并，不保留逐字符次数；这不是 iCloud 真机验证结果。


## 记住登录（2026-09-11）

用户明确授权成功登录后保存凭据，以便以后无需重复输入。新增登录页「记住登录」默认开启；使用微信原生异步加密存储接口，最低支持版本 2.21.3，项目基础库已高于此要求。无法加密时提示用户，不写明文。保存时机为学校认证及课表验证成功后，后续考勤断网仍保留已验证的登录。

冷启动按需自动认证；过期后最多一次自动重登；AUTH_REQUIRED 停止并删除凭据，网络错误保留凭据。退出登录、清除数据、显式换账号都会取消原会话并清除凭据。加密写入使用串行队列和立即禁用标记，避免退出时迟到写入重新启用登录。旧月份考勤在自动重登时保留，显式换账号成功时清除。
