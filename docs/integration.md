# 学校系统接入设计

> 更新：2026-09-11 独立验证页已通过真实账号的手机测试：直接认证并读取课表、考勤，本次考勤访问需 VPN。此链路不依赖自建后端，主页面已接入手动同步，新月汇总接口及主页面需手机验收，详见 [验证记录](login-verification.md)。下文后端 API 是备选设计，不代表唯一方案。

## 当前边界

主页面支持学校登录后的真实课表、按月考勤同步，保留演示模式和离线缓存；独立实验页已通过直接认证及课表、考勤读取验证。同步数据仅缓存在当前微信本机。下文后端接口仅为备选设计，当前实现直接请求学校。

原 Android 项目直接复用学校 WebView Cookie、通过 evaluateJavascript 提取网页内容。微信 `web-view` 公开能力不能替代这套桥接机制。根据 2026-09-11 读取的官方文档，个人类型小程序暂不支持 web-view，其他网页需配置业务域名；postMessage 也仅在特定时机向小程序发送消息。

来源：https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html

学校现有登录页如果没有主动配合小程序，不能仅靠嵌入页面获取认证后的数据。独立验证页通过 wx.request 完成认证与业务接口读取，已进行本人账号的真机测试；未保存真实业务内容。

## 备选：学校支持的后端接入流程

1. 确认 AppID、主体，以及学校能否提供统一认证对接或官方 API。
2. `wx.login` 获取一次性 code，交给获批准的服务端验证微信身份；AppSecret 仅保存在服务端。
3. 学校支持的认证流程将微信用户与校园身份绑定。校方可提供一次性绑定码或适配的 SSO 回调，具体取决于对接能力；不应在小程序中假造校园密码登录框。
4. 服务端通过学校许可的方式按用户读取课表、考勤。若学校系统只在校园网络可达，部署位置也需具备访问条件。
5. 返回标准化业务数据，小程序校验成功后原子替换该账号的缓存。过期或网络失败保留缓存、明确显示上次同步时间。切换账号必须隔离或清除前一账号的数据。

请求域名和微信账号能力需在真机环境验证，不能以开发者工具关闭校验作为上线方案。

## 建议 API 合约（待实现）

| 接口 | 用途 |
| --- | --- |
| `POST /v1/session/wechat` | 接收微信 code，创建小程序服务会话 |
| `POST /v1/account/bind` | 交换校方一次性授权结果，绑定校园身份 |
| `GET /v1/campus/snapshot` | 返回当前账号完整课表、考勤快照 |
| `DELETE /v1/session` | 退出并撤销会话 |

snapshot 成功体采用 `examples/campus-data.json` 格式，附加服务端 `updatedAt` 与不含个人标识的会话关联信息；客户端适配层仅把经过校验的业务字段传入仓库。前端区分 `SESSION_EXPIRED`、`SCHOOL_UNREACHABLE`、`SCHEMA_CHANGED`、`SERVER_ERROR`，失败不能变成空课表。不要把部分月份结果当完整快照覆盖历史记录。

直接请求适配器位于 `miniprogram/services/campus.js`，转换位于 `campus-data.js`。按月同步仅替换对应月份；新账号首次课表同步会清除旧账号考勤缓存；会话仅保存在内存，密码不持久化。

## 微信开发者工具验收

- 编译全部五个页面，无 WXML/WXSS 组件错误。
- 320/375/430 宽度及大字体下检查标题、周导航、课程名称、tabBar。
- 同步学校数据；重启仍保留；查看指定教学周与 2026-09 月份。
- 校验重复日期、错误日期、非法时间，确认报错且旧缓存仍在。
- 取消覆盖确认，确认旧数据仍在。
- 修改个人目标，不应改变学校合格状态。
- 切换月份、周次无记录时展示空态。
- 清除本地数据回到明确标注的演示模式。
- 无网络下查看已缓存数据。
- 真机验证聊天文件选择、长 JSON 输入与本地存储失败提示。
